Ansible 自動化測試 / smoke-test

整個專案的設計哲學是「證據優先」——每個結論都要有實測數字 支撐,不接受「理論上應該可以」。playbooks/k8s/smoke-test.yml 把整個建置過程反覆手動驗證的步驟,收斂成一個可以重複執行、自動判斷 成敗的 playbook,讓你自己也能隨時重新確認整個系統真的在動。

怎麼跑
$ scripts/ansible.sh ansible-playbook playbooks/k8s/smoke-test.yml

四段驗證,由淺到深

1. 節點 / 系統 pod Ready

最基本的健檢
kubectl wait --for=condition=Ready node --all --timeout=60s
kubectl wait --for=condition=Ready pod --all -n kube-system --timeout=120s

用 kubectl 內建的 wait --for=condition=Ready,不是 自己解析 kubectl get nodes 的輸出字串——這是最直接、 最不容易誤判的檢查方式:條件不滿足就會逾時失敗,ansible task 直接報錯,不需要額外寫判斷邏輯。

2. apiserver haproxy backend 健康狀態

讀 tor 上 haproxy 的 CSV 格式統計頁面,確認 3 台 master 全部 UP。這裡有個容易忽略的細節:haproxy CSV 的 status 欄位是第 18 欄,不是緊接在 server 名稱後面 ——中間還有 qcur/qmax/scur 等一堆欄位,不能直接對整行字串做 contains 比對, 要先用 cut -d, -f1,2,18 精確取出 pxname,svname,status 三個欄位再比對。

3. FRR/BGP PodCIDR 傳播數量

在 tor 上數 show ip bgp 裡標記 *>i (valid + best + internal)的條目數量,確認剛好等於 groups['k8s_nodes'] | length(目前是 7)——每個 k8s 節點恰好一條 PodCIDR,不多不少。這一段只證明「路由存在」, 還不能證明「路由真的能用」,所以還需要第四段。

4. 跨節點 pod-to-pod 連線測試(最重要的一段)

這是唯一一段會建立真實資源、實際發送流量的測試——在 groups['masters'][0](ms-0001)跟 groups['workers'][-1](ap-0002)上各建 一個 busybox pod,B 跑一個小型 httpd,A 用 wget 連 B 的 pod IP,斷言拿到預期的回應內容。

清掉舊測試 pod
ignore_errors 式保險
→
建 pod A + pod B
各自釘在不同節點
→
A wget B 的 pod IP
斷言回應內容
→
always: 清掉測試 pod
不管成功失敗都執行

整段包在 block/always 裡——不管中間哪一步 失敗,always 都會執行清掉測試 pod,不會在叢集裡留下垃圾。 這個測試不只是「有沒有連通」,而是直接對應 網路架構總覽裡描述的 「情境二:Pod ↔ Pod 跨節點」——如果這段測試過,代表 Cilium native routing + FRR fabric 的整條路徑真的在動, 不是只有設定看起來對。

寫這個 playbook 時撞到的兩個 ansible 陷阱

📊

haproxy CSV 欄位位置

第一版直接對整行字串找 server,UP,永遠比對不到 ——status 欄位在很後面,中間隔了十幾個欄位,必須先 cut 取出正確欄位才能比對。

🔤

command 模組的 JSON 引號陷阱

ansible.builtin.command 給純字串時不走 shell,靠 shlex 解析——--overrides={"spec":...} 裡的雙引號會被當成 shell quoting 字元吃掉,變成不合法 JSON。 改用 argv: list 形式徹底避開這個解析問題。

可重複執行性:實測驗證過

這個 playbook 連續執行兩次,兩次都完全成功(第二次沒有任何 殘留狀態造成的干擾)——這也是它能被稱為「smoke test」而不只是 「一次性驗證腳本」的原因:任何時候懷疑系統壞了,直接重跑一次, 不需要事先手動清理什麼。

Makefile:一個跟測試無關,但同樣是「讓你自己能動手」的小工具

Makefile
$ make ssh
# 讀 terraform output -raw bastion_floating_ip,直接 ssh 進 bastion
# 不用每次手動查 IP、拼 ssh 指令

跟 scripts/ansible.sh 用同一把私鑰(解密自 ansible/inventory/group_vars/all/vault.yml 的 vault_ssh_private_key,見 Ansible 框架設計的「私鑰處理」 一節),差別是 make ssh 給你一個真正互動式的 shell (scripts/ansible.sh 只負責觸發 ansible 指令,不是 給你互動操作用的)。make 不帶參數會印出 help(.DEFAULT_GOAL := help),避免不小心 打錯指令直接觸發 SSH 連線。
