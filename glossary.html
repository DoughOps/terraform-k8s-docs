開始 術語表

這頁收錄文件站會用到的術語，每個術語兩三句話解釋，並連到詳細說明的頁面。第一次讀到不熟的名詞時，來這裡找錨點。其他頁連到本頁時，網址是 glossary.html#術語id，例如 glossary.html#route-reflector。

網路與路由

這些術語構成 Lab 的資料平面。先讀 網路架構總覽，再回來查細節。

BGP

Border Gateway Protocol，路由器之間交換「某個網段怎麼到達」的協定。Lab 用它讓節點彼此知道對方的 Pod CIDR。實作是 FRR，見 FRR / iBGP Fabric。

iBGP

同一個 ASN 內部的 BGP 連線。Lab 的所有節點都屬於 ASN 65000，彼此以 iBGP 交換路由。iBGP 預設不會把學到的路由再轉給其他 iBGP 鄰居，所以需要 route reflector。

ASN

Autonomous System Number，BGP 用來識別一個管理單位的編號。Lab 全部節點共用私有 ASN 65000。此值在 Terraform 與 Ansible 兩邊各設一次，需手動保持一致。

route reflector

路由反射器，讓 iBGP 節點不必兩兩建立連線。Lab 的 tor 是唯一的 route reflector，所有節點只與它建立連線，它再把路由反射給其他節點。見 FRR / iBGP Fabric。

next-hop-self

讓 route reflector 在反射路由時，把下一跳改成自己。k8s-net 是一個扁平 L2 網段，沒有這個設定，節點會學到指向彼此真實 IP 的路由並直接 ARP，tor 就不再是唯一的 L3 跳點。設計見 FRR / iBGP Fabric。

ECMP

Equal-Cost Multi-Path，同一個目的地有多條成本相同的路徑時，流量分散到全部路徑。Lab 用 maximum-paths ibgp 開啟。它是 DSR L4LB 設計的基礎，見 DSR / L4LB 歷史。

DSR

Direct Server Return，負載平衡器只處理進來的封包，回程封包由後端直接送回客戶端，不經過負載平衡器。Lab 驗證過這個設計，現在處於休眠狀態，見 DSR / L4LB 歷史。

L4LB

第 4 層（TCP／UDP）負載平衡器。Lab 原本用 l4- 節點跑 IPVS DR，並透過 BGP 宣告 Service VIP。現在 l4- 節點當一般 worker 使用，外部流量改走 Cloudflare Tunnel。

FRR

Free Range Routing，Linux 上的開源路由軟體套件，Lab 用它在每個節點跑 BGP。見 FRR / iBGP Fabric。

zebra

FRR 的核心 daemon，負責把 BGP 等協定學到的路由寫進 Linux 核心的路由表。BGP daemon 本身不直接改核心路由，要經過 zebra。

TOR

Top-of-Rack，原指機櫃頂端的交換器。Lab 用一台 VM 扮演它：它是 k8s-net 的 L3 fabric router 與唯一 route reflector，也跑 apiserver 的 haproxy。見 網路架構總覽。

bastion

Lab 唯一的 SSH 與維運入口，Floating IP 綁在它身上。Ansible 的 Docker container 也跑在 bastion 上，並透過 mgmt-net 直連所有節點。Vault、Keycloak、GitLab 也跑在這台。

Neutron

OpenStack 的網路服務，管理網路、子網、Router、安全群組與 port。Lab 的 k8s-net 與 mgmt-net 都是 Neutron 建立的。見 Terraform / OpenStack。

port security

Neutron 對每個 port 做的防偽造檢查，包含來源 IP／MAC 檢查和以 conntrack 為基礎的安全群組。Lab 的 fabric port 全部關閉它，因為 DSR 的回程封包不經過原本的 port，conntrack 會把它當成無效狀態丟掉。見 Terraform / OpenStack § port security。

Floating IP

OpenStack 上可以綁定到 VM 的對外 IP。Lab 的 Floating IP 綁在 bastion，只供 SSH 與維運。對外網頁流量不經過它。

SNAT

Source NAT，把封包的來源位址改成 Router 的位址。mgmt-net 的 Neutron Router 做 SNAT，讓節點能連到外網拉 image 與套件。

native routing

Pod 的 IP 直接在底層網路上被路由，不封裝。Lab 用 Cilium native routing，由 FRR 把各節點的 Pod CIDR 宣告進 fabric。見 Role: cilium。

VXLAN／Geneve overlay

把 Pod 封包封裝進 UDP 隧道再送到對方節點的做法，底層網路不需要認識 Pod IP。代價是額外的封裝開銷和較難觀察的路徑。Lab 刻意不用它。

eBPF

Linux 核心內可安全執行小程式的機制。Cilium 用它實作封包轉發、Service 負載平衡和網路觀測。

PodCIDR

分配給 Pod 的 IP 範圍。Lab 的整體範圍是 172.16.0.0/16，每個節點分到一個 /24，由 Cilium 分配、FRR 宣告。

Service CIDR

分配給 Kubernetes Service（ClusterIP）的虛擬 IP 範圍，Lab 是 172.18.0.0/16。這些位址不屬於任何網卡，由 Cilium 在節點上轉成後端 Pod。靜態路由概念見 網路架構總覽 § service-cidr。

Kubernetes 元件

kubeadm

Kubernetes 官方的叢集引導工具。Lab 用它初始化第一台 master，再 join 其他控制平面與 worker。見 Role: kubeadm。

etcd

Kubernetes 儲存所有叢集狀態的分散式鍵值資料庫。3 台 master 各跑一個 etcd 成員。叢集重建後 etcd 是全新的，所以需要保留的資料另存於 bastion 的持久碟。

CRI-O

專為 Kubernetes 設計的 container runtime，實作 CRI 介面。見 Role: crio。

haproxy

TCP／HTTP 負載平衡器。Lab 在 tor 上用它把 apiserver 的固定進入點 k8s-api.internal 分散到 3 台 master。見 Role: apiserver-lb。

kube-proxy

Kubernetes 預設用來實作 Service 轉發的元件，用 iptables 或 IPVS 規則。Lab 把它完全拿掉，由 Cilium eBPF 取代。見 Role: cilium § kube-proxy 取代。

CNI

Container Network Interface，Kubernetes 的網路外掛標準，負責給 Pod 配 IP 與設定網路。Lab 的 CNI 是 Cilium。

Cilium

以 eBPF 為基礎的 CNI。Lab 用它的 native routing 模式、取代 kube-proxy，但不使用它自己的 BGP Control Plane，因為 BGP 已由 FRR 負責。見 Role: cilium。

Hubble

Cilium 內建的網路觀測元件，能看到 Pod 之間的即時流量。Hubble UI 的網址見 叢集使用手冊 § 服務。

Istio

Service mesh 與 ingress 層。Lab 只用它的 ingress gateway 做叢集內的 L7 路由，安裝在 istio namespace。見 Role: istio。

Gateway／VirtualService

Istio 的兩個資源。Gateway 定義入口監聽哪些 hostname 與連接埠，VirtualService 定義某個 hostname 的請求要送到哪個 Service。Lab 所有服務共用 istio/k8s-gateway，各自建立自己的 VirtualService。範例見 叢集使用手冊 § 部署。

對外入口與身份驗證

Cloudflare Tunnel

由叢集內的 cloudflared 主動連出到 Cloudflare 邊緣，建立 outbound-only 的隧道。外部請求沿隧道進來，叢集不需要開任何 inbound port。見 Role: cloudflare_tunnel。

Cloudflare Access

Cloudflare 在邊緣提供的身份驗證閘門。Lab 的 *.dough-ops.com 全部掛在它後面，只放行指定 GitHub org 的成員。規則見 Cloudflare 設定清單。

Access for SaaS

Cloudflare Access 讓自己扮演標準 OIDC provider 的模式，應用程式可以把它當 IdP 使用。它簽發的 id_token 效期固定 5 分鐘，且不發 refresh_token，這是 ArgoCD 需要內建 Dex 的原因，見 Role: argocd § 登入。

Origin CA

Cloudflare 簽發的源站憑證，只被 Cloudflare 邊緣信任，瀏覽器不信任。Lab 用它在 Istio Gateway 提供 HTTPS，見 Role: cert_manager。

Full (strict)

Cloudflare 的 SSL／TLS 模式：邊緣到源站也用 HTTPS，並驗證源站憑證的有效性。Lab 搭配 Origin CA 達到端對端加密。

OIDC

OpenID Connect，建立在 OAuth 2.0 上的身份驗證協定。應用程式把登入導向 IdP，拿回帶有使用者身份的 id_token。Lab 的各服務登入幾乎都用它，流程見 身份聯邦登入流程。

id_token

OIDC 登入成功後簽發的 JWT，內含使用者的身份 claims，如 email 與簽發者 iss。接收端靠簽章與效期驗證它。

IdP

Identity Provider，負責驗證使用者並簽發身份憑證的系統。Lab 裡 Cloudflare Access、Keycloak、Dex 都扮演過 IdP 的角色。

SSO

Single Sign-On，登入一次就能使用多個服務。Lab 讓通過 Cloudflare Access 的人，在 Grafana、Vault、ArgoCD、GitLab 等服務上免密碼登入。

Dex

開源的 OIDC broker，對應用程式提供標準 OIDC 介面，後面轉接到不同的 connector。Lab 有兩個用途：叢集的 Dex 轉接 Keycloak，ArgoCD 內建的 Dex 轉接 Cloudflare Access。見 Role: keycloak / dex。

Keycloak

開源的身份與存取管理系統，Lab 用它模擬獨立於叢集的公司 SSO，跑在 bastion 的 Docker 上。見 Role: keycloak / dex。

oauth2-proxy

擋在應用程式前面的認證反向代理。它自己不管理使用者，只認一個上游 OIDC provider，驗證通過後把身份轉成 HTTP header 交給後端。見 身份聯邦登入流程。

儲存與平台服務

PVC／PV

PersistentVolume（PV）是叢集裡的一塊儲存，PersistentVolumeClaim（PVC）是 Pod 對儲存的申請。Lab 的監控資料用固定名稱的靜態 PV，才能在整個環境重建後重新綁回舊資料，見 內部工具 § 監控資料的儲存。

CSI

Container Storage Interface，Kubernetes 接儲存後端的標準介面。Lab 用 nfs.csi.k8s.io 驅動，提供 nfs-csi 與 nfs-csi-retain 兩個 StorageClass。

NFS

網路檔案系統。bastion 把持久碟匯出成 NFS，供叢集內的 PV 使用。資料碟在 terraform destroy 後保留，見 Terraform / OpenStack § 資料碟。

Vault

HashiCorp 的秘密管理系統。Lab 跑在 bastion 上，資料放在持久碟，重建後只需要自動 unseal。見 Role: vault。

VSO

Vault Secrets Operator，在叢集內把 Vault 的資料同步成一般的 k8s Secret。用法見 叢集使用手冊 § 部署。

GitOps

把期望的叢集狀態存在 Git 裡，由工具持續比對並套用的做法。Lab 用 ArgoCD 實現，repo 來源包含自架 GitLab。

ArgoCD

GitOps 持續部署工具，監看 Git repo 並把 manifests 同步到叢集。Lab 的 ArgoCD 裝在它所管理的叢集內，見 Role: argocd。

ansible-vault

Ansible 內建的檔案加密工具。Lab 的 SSH 私鑰與 secrets.yml 都以它整檔加密後進版控，密碼放在不進版控的 .env。見 Ansible 框架設計 § 密鑰管理。
