把資料中心的每一層,自己蓋了一遍

沒有用雲端幫忙藏起來的路由、負載平衡、身份驗證——這是一個從網路架構開始, 一路蓋到生產級 Kubernetes 平台的完整專案。九台虛擬機、一份 BGP 路由設定, 模擬出跟實體機房一樣的網路拓撲,再把服務網格、憑證管理、零信任存取、 持久化儲存一層一層疊上去。以下是目前完成的部分。

01 / Foundation

基礎建設

雲端平台通常會把路由跟負載平衡藏在一個按鈕後面。這裡刻意不用那顆按鈕—— 九台虛擬機用真正的 BGP 協定互相交換路由,行為跟一間實體機房裡的交換器/路由器架構一模一樣。

tor — vtysh -c "show ip bgp summary"
# 每一台節點的路由都由 tor 集中反射出去,示意輸出 tor# show ip bgp summary Neighbor V AS MsgRcvd MsgSent State bastion-fabric 4 65000 1442 1440 Established ms-0001 4 65000 1518 1519 Established ms-0002 4 65000 1517 1518 Established ms-0003 4 65000 1516 1518 Established l4-0001 4 65000 1503 1502 Established l4-0002 4 65000 1501 1500 Established ap-0001 4 65000 1490 1491 Established ap-0002 4 65000 1489 1490 Established Total number of neighbors 8, all Established
Terraform
一份設定檔建出所有虛擬機、網路與防火牆規則。 整個環境可以砍掉重練,而且每次重建的結果都一致——不用擔心「上次是手動改的哪裡」。
FRR + iBGP Fabric
用真正的 BGP 路由協定串起每個節點,模擬實體資料中心裡路由器交換路徑的方式。 單一節點當 Route Reflector,其餘節點互相學到路由,不用兩兩互聯。
TOR 路由層
單一節點集中處理對外連線與路由反射,其餘節點專心處理運算,職責分工清楚。
02 / Platform

容器平台

在這套網路基礎上,架起一座完整的 Kubernetes 叢集。連 Pod 跟 Pod 之間怎麼互相找到彼此, 都直接借用第一層已經蓋好的 BGP 路由,不用另外疊一層 overlay 網路。

Pod 網路怎麼互相找到彼此 kube-proxy vs. Cilium eBPF
kubeadm
建立多台控制平面節點組成的高可用 Kubernetes 叢集核心。
CRI-O
輕量、專為 Kubernetes 設計的容器執行環境。
Cilium
用 eBPF 取代傳統 kube-proxy,並直接跟資料中心的 BGP 路由整合,Pod 流量原生可路由。 連叢集內部流量的即時觀測(Hubble)也是 Cilium 內建的,不用額外再裝一套。
03 / Traffic

流量與安全

服務怎麼互相溝通、又怎麼被安全地曝露到外面。負載平衡這一段刻意不用雲端的黑盒子—— 回應流量直接從真正處理請求的節點送回去,不繞回負載平衡器再轉一手。

DSR:回應流量不繞路 Direct Server Return
Istio
服務網格,統一管理叢集內部的流量與對外的入口閘道。
cert-manager
自動簽發、自動更新 HTTPS 憑證,不用再手動盯著到期日。
DSR 負載平衡
節點自己用 BGP 宣告服務位址,回應流量直接送回客戶端,不繞經負載平衡器。
04 / Access

零信任對外存取

不開放任何固定 IP 或對外 Port,身份驗證全部交給 Cloudflare 的 Zero Trust 架構—— 連要 SSH 進維運主機,都是先驗證身份、再透過加密通道連進去,不是先開一道門再檢查。 而且身份來源只有一個:GitHub 組織成員資格,不是另外一套帳號系統。

一個身份,自動打通三個地方 GitHub Org → Cloudflare Access SSO
Cloudflare Tunnel
叢集主動連出去建立通道,不需要對外開放任何 Port 或固定 IP。
Cloudflare Access
身份來源直接綁定 GitHub doughops 組織——加入組織,就自動拿到網站存取權,不用另外幫每個人開帳號。 同一次登入還會自動延伸成兩件事:Grafana 免再登入一次(SSO),Kubernetes Dashboard/API 的權限也照身份自動對應(OIDC → RBAC),不用逐一手動設定。
Cloudflare 瀏覽器 SSH
不用安裝任何用戶端,打開瀏覽器就能安全連進維運主機。
05 / Storage

持久化儲存

讓應用程式的資料,撐得過任何一次環境重建。就算整台虛擬機被砍掉重建, 真正重要的資料還是留在獨立掛載的硬碟上,不會一起消失。

多個 Pod,同一份資料 ReadWriteMany
持久化雲端硬碟
獨立掛載、不隨主機生命週期消失的儲存空間,重建機器也不會弄丟資料。
NFS CSI Driver
讓 Kubernetes 原生支援多個 Pod 同時讀寫同一份資料。

07 / Automation

自動化維運

整套環境,幾道指令就能從無到有重建一次。每一個設定步驟都寫成可以重複執行的腳本, 不用靠人記得「上次是怎麼弄好的」。

從零開始建置整個平台 — 示意輸出
$ scripts/ansible.sh ansible-playbook playbooks/bastion.yml ... 裝好 NFS、Cloudflare Tunnel、kubectl ... PLAY RECAP ********************************* bastion : ok=48 changed=6 failed=0 $ scripts/ansible.sh ansible-playbook playbooks/k8s.yml ... CRI-O → kubeadm → Cilium → Istio → cert-manager → ... ... PLAY RECAP ********************************* bastion : ok=210 changed=94 failed=0
Ansible
所有設定步驟都寫成可重複執行的自動化腳本,不靠記憶手動操作。
GitHub Actions Runner
自架的 CI/CD 執行環境,直接跑在自己蓋的平台上。
這不是為了展示技術而堆疊技術——而是想搞懂,當雲端把一切都幫你藏起來之後, 一座真正的資料中心到底是怎麼運作的。
