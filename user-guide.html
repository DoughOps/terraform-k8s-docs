開始 叢集使用手冊

這頁給叢集已經在運作的使用者：怎麼連進去、怎麼部署一個網頁、有哪些服務可用，以及每個服務登入後你有什麼權限。想了解底層原理，每一節都連到對應的深入頁。

連線到叢集

bastion 是唯一的操作入口。tor、master、worker 都在沒有對外路由的 k8s-net 上，無法從外部直接連。要操作叢集，先連上 bastion。

方法一：make ssh

這個方法需要 clone 這個 repo，並取得 .env。.env 內要有 ANSIBLE_VAULT_PASSWORD，以及讀 Terraform state 用的 AWS_ACCESS_KEY_ID 和 AWS_SECRET_ACCESS_KEY。.env 不進版控，向專案管理者索取。

repo 根目錄
$ make ssh
# 解密共用私鑰，讀 terraform output 取得 bastion 的 floating IP，再 ssh 進去
# 登入身份是 ubuntu，不是 root

預期結果：你直接落在 bastion 的 shell。私鑰的存放與解密方式見 Ansible 框架設計 § 密鑰管理，其他 Makefile 指令見 § Makefile。

方法二：瀏覽器終端機

你是 doughops GitHub org 成員但沒有 repo 存取權時，可以開 https://ssh.dough-ops.com/。Cloudflare Access 驗證 GitHub 身份後，會在瀏覽器裡渲染一個終端機。

這條路只是換一個網路入口，沒有另一套身份系統。Cloudflare Access 只決定你的連線能不能抵達 bastion 的 22 port，SSH 認證仍然使用同一把共用私鑰。所以光是 org 成員身份無法登入 bastion，你的 SSH client 仍需持有私鑰。叢集沒有「每人一把 key」的機制，這是已知限制，見本頁已知限制。Access 規則見 Cloudflare 設定清單。

連進去之後

bastion 已經裝好這些工具，細節見 Role: kubeadm：

工具說明
kubectlkubeconfig 放在 ~/.kube/config，直接使用，不用 export KUBECONFIG
kkubectl 的 alias，附 tab 自動補全
k9s互動式 terminal UI，瀏覽 pod、看 log、exec 比 kubectl get 直覺
helm裝在 /usr/local/bin，叢集內每個 helm-based 元件都是用它安裝，版本與叢集元件對齊

部署一個網頁

最小流程分四步：寫一份 manifest，包含 Namespace、Deployment、Service 和 VirtualService，執行 kubectl apply，等 rollout 完成，再開瀏覽器。下面這份沿用 Role: istio 的 demo app 的模式，不需要自己準備 container image：用 ConfigMap 把靜態頁掛進 nginx。把 <your-name> 換成你的名稱就能跑。

~/my-app.yaml（在 bastion 上）
apiVersion: v1
kind: Namespace
metadata:
  name: <your-name>
  labels:
    istio-injection: enabled   # 要走 Istio Gateway 就一定要這個 label
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-html
  namespace: <your-name>
data:
  index.html: |
    <html><body><h1>Hello from <your-name></h1></body></html>
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: <your-name>
spec:
  replicas: 2
  selector:
    matchLabels: { app: web }
  template:
    metadata:
      labels: { app: web }
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpine
          ports: [{ containerPort: 80 }]
          volumeMounts:
            - { name: html, mountPath: /usr/share/nginx/html }
      volumes:
        - name: html
          configMap: { name: web-html }
---
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: <your-name>
spec:
  selector: { app: web }
  ports: [{ name: http, port: 80, targetPort: 80 }]
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: web
  namespace: <your-name>
spec:
  hosts: ["<your-name>.dough-ops.com"]
  gateways: ["istio/k8s-gateway"]   # 整個叢集共用的 Gateway，跨 namespace 引用
  http:
    - route:
        - destination:
            host: web.<your-name>.svc.cluster.local
            port: { number: 80 }
部署
$ kubectl apply -f ~/my-app.yaml
$ kubectl -n <your-name> rollout status deployment/web --timeout=120s
# 成功之後開瀏覽器：https://<your-name>.dough-ops.com/

預期結果：rollout 顯示 successfully rolled out，瀏覽器能開啟網址並看到 Hello 頁面。第一次開網址會先經過 Cloudflare Access 登入。

部署前先知道的事

🔑

網址自動被 Cloudflare Access 擋住

*.dough-ops.com 掛在同一個萬用字元 Access Application 下。你的新網址不需要額外設定，就套用同一條規則：只有 doughops GitHub org 的成員看得到。要開放給所有人，需在 Cloudflare 另建 bypass 規則，這不屬於 ansible 管理的範圍，原則見 Cloudflare 設定清單。

🌐

hostname 要在 *.dough-ops.com 底下

共用 Gateway istio/k8s-gateway 只監聽這個萬用字元，用其他網域連不進來，見 Role: istio。

📦

image pull 不用另外設定

節點走 mgmt-net 的 SNAT 出口，公開 image（Docker Hub、GHCR 等）直接拉得到。私有 registry 照 Kubernetes 標準做法帶 imagePullSecrets，叢集沒有額外限制。

💾

需要持久化儲存就掛 PVC

兩個 StorageClass 都是 ReadWriteMany，後端同一個 NFS：nfs-csi 在 PVC 刪除時一併刪資料，nfs-csi-retain 則保留資料。想要「誤刪 PVC 也不丟資料」的保險就選後者。

🔑

密鑰放 Vault，不寫進 manifest

叢集裝了 vault-secrets-operator。任何 namespace 建一個 VaultStaticSecret，就會同步出一般的 k8s Secret，掛載方式與平常的 envFrom、volumeMounts 相同。全部 namespace 已接好共用的預設 vaultConnectionRef 與 vaultAuthRef，你不用另外指定。

下面是 Vault 的範例。先放一筆資料，再建 VaultStaticSecret。

先在 Vault 裡放一筆（從 bastion，或用 vault.dough-ops.com 的 UI）
$ vault kv put secret/<your-name>/db-password value=hunter2
在你的 namespace 裡建 VaultStaticSecret
apiVersion: secrets.hashicorp.com/v1beta1
kind: VaultStaticSecret
metadata:
  name: db-password
  namespace: <your-name>
spec:
  type: kv-v2
  mount: secret
  path: <your-name>/db-password
  destination:
    name: db-password-secret   # 同步出來的 k8s Secret 名稱
    create: true
  refreshAfter: 1h              # Vault 裡改了值，最晚等這麼久會自動重新同步

預期結果：幾秒後 kubectl -n <your-name> get secret db-password-secret 看得到同步出來的 Secret。

有哪些服務可以用

所有服務走同一條路徑：*.dough-ops.com → Cloudflare Tunnel → Istio ingress gateway → 各自的 VirtualService。預設只有 doughops GitHub org 成員通過 Cloudflare Access 後才連得到，只有標「公開」的兩項例外。每個服務登入後的權限見權限矩陣。hostname 以 ansible/inventory/group_vars/all/main.yml 為準。

權限矩陣

登入之後你能做什麼，由服務決定，共有兩種模型。預設唯讀：通過 Cloudflare Access 的 org 成員只有唯讀或少量寫入權限，oidc_admin_emails 名單內的人才有完整寫入。登入即 admin：通過 Cloudflare Access 的 org 成員一律是 admin，沒有分層。下表只寫角色層級，不列個別帳號。

oidc_admin_emails 是 secrets.yml 內的 email 清單，預設為空。清單為空時沒有人拿到寫入權限。清單由 oidc_rbac、kube_prometheus_stack、gitlab_server 三個 role 共用，檔案管理見 Ansible 框架設計 § 密鑰管理。

Kubernetes Dashboard預設唯讀內建 view（namespace 內資源，不含 secrets、roles、rolebindings）。cluster 範圍唯讀 nodes、namespaces、PV、StorageClass。額外三個寫入：刪 pod、改 configmap、scale deploymentcluster-admin無

Kubernetes 權限怎麼來

Dashboard 前面的 Istio EnvoyFilter 把 Cloudflare Access 簽發的 JWT 複製到 Authorization header。kube-apiserver 信任同一個 JWT 當 OIDC 身份（oidc_auth role），身份是 email。oidc_rbac role 再依身份綁定 RBAC：

  • cloudflare-access-oidc-view：把內建 view 綁給 system:authenticated。
  • cloudflare-access-oidc-default：疊加 cloudflare-access-default ClusterRole，補 cluster 範圍的唯讀和三個寫入操作。
  • cloudflare-access-oidc-admin：把 cluster-admin 綁給 oidc_admin_emails 內的人。名單為空時不建立這個綁定。

預設權限刻意不含 secrets。RBAC 沒有排除語法，若用 resources: ["*"] 做唯讀，會連 secrets 都讀得到，所以改用內建 view 加明確列舉。

已知限制

  • ArgoCD 的長效 token 與 admin：ArgoCD 走內建 Dex，簽發給 ArgoCD 的 id_token 效期是 8760h（1 年），好處是不會每 5 分鐘被登出。代價是 token 外流後一年內有效，而且權限是 admin。ArgoCD 的 in-cluster target 用 ServiceAccount 管理叢集，admin 能建立 Application 部署資源，影響範圍接近整個叢集。調低 argocd_dex_id_token_expiry 可以縮短暴露期，代價是更常重新登入。設計理由見 Role: argocd § 登入。
  • Vault 與 ArgoCD 的全員 admin：org 成員等同這兩個服務的管理者，沒有最小權限分層。影響範圍是 Vault 內所有 secrets 和 ArgoCD 管理的所有工作負載。信任邊界就是 GitHub org 的成員資格。
  • 共用 SSH 私鑰：全部節點使用同一把 SSH key，沒有每人一把的機制。私鑰外流時影響所有節點。細節見 Ansible 框架設計 § 密鑰管理。
  • 只靠 Access 的服務：Hubble、Prometheus、Alertmanager 沒有內建登入，Cloudflare Access 是唯一的一道門。Access 設定錯誤或被繞過時，這些服務完全沒有第二層防護。
  • 機器對機器的 bypass：Keycloak 的 realm 端點與 GitLab 的 git、API 路徑，因為非互動存取需要而繞過 Cloudflare Access，改由服務自己的認證把關。原則與縮小範圍的方式見 Cloudflare 設定清單。
