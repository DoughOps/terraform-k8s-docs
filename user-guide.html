叢集使用手冊我只是想用這個叢集,不是想重建它

這頁跟其他頁不一樣——其他頁在講「這個系統為什麼長這樣、怎麼從零建出來」,這頁只講 叢集已經活著的情況下,一個使用者實際會做的三件事:連進去、部署一個網頁、 知道現在有哪些東西可以用。想理解底層原理,每一節都有連到對應深入頁面的連結。

1. 連線到 Cluster

bastion 是唯一的入口——其他所有節點(tor、master、worker、L4LB)都在 沒有對外路由的 k8s-net 上,沒有辦法從外部直接連。想操作叢集,一律先連上 bastion。

方法一:make ssh(需要 repo + vault 密碼)

在你自己的機器上(repo 根目錄)
$ make ssh
# 解密共用私鑰 → 讀 terraform output 拿 bastion 的 floating IP → ssh 進去
# 直接落地是 ubuntu 這個使用者,不是 root

前提是你已經 clone 這個 repo,而且拿到 .env 裡的 ANSIBLE_VAULT_PASSWORD(跟你的專案管理者要,這個檔案本身不進版控)。 私鑰本身不是明碼檔案,是 ansible/inventory/group_vars/all/vault.yml 裡 vault 加密過的內容,make ssh 會自動處理解密,你不需要手動做任何事。 進去之後就是一個正常的 shell,細節見 Ansible 框架設計的「私鑰處理」一節。

方法二:瀏覽器內建終端機(ssh.dough-ops.com)

如果你是 doughops GitHub org 成員、但沒有 repo/vault 存取權,可以改用 這條路:瀏覽器直接開 https://ssh.dough-ops.com/, Cloudflare Access 驗證你的 GitHub 身份後,直接在瀏覽器裡渲染出一個終端機。

注意:這條路只是換一個網路入口,不是另外一套身份系統——Cloudflare Access 在這裡只負責「要不要讓你的連線抵達 bastion 的 22 port、要不要在瀏覽器裡渲染 終端機介面」,實際的 SSH 認證(哪把 key 才能登入)完全沒有改變,還是同一把 ansible/files/ssh/id_ed25519 共用私鑰。換句話說:光是「doughops org 成員」這個身份,還不足以讓你透過這條路真的登入 bastion——你的 SSH client 仍然需要 持有那把私鑰(或已經被信任的其他 key)。目前這個叢集沒有「每個人各自 一把 key」的機制,見 Cloudflare 手動設定清單 了解這條 tunnel 的完整設定。

連進去之後

bastion 上已經幫你裝好、設定好這些東西(見 Role: kubeadm/框架設計), 不需要再自己裝:

工具說明
kubectlkubeconfig 已經放在 ~/.kube/config,直接用,不用另外 export KUBECONFIG
kkubectl 的 alias,加上 tab 自動補全,少打幾個字
k9s互動式的 terminal UI,瀏覽 pod/log/exec 比純 kubectl get 直覺
helm裝在 /usr/local/bin,叢集內每個 helm-based 元件都是用它裝的,版本跟叢集元件對齊

2. 部署一個網頁

最小可行的流程:寫一個 manifest(Namespace + Deployment + Service + VirtualService)、kubectl apply、等 rollout 完成、開瀏覽器看結果。下面這份 直接照抄 roles/demo_app 的模式,不用自己準備 container image(用 ConfigMap 掛一個 nginx 靜態頁面進去),換掉 <your-name> 就能跑。

~/my-app.yaml(在 bastion 上)
apiVersion: v1
kind: Namespace
metadata:
  name: <your-name>
  labels:
    istio-injection: enabled   # 要走 Istio Gateway 就一定要這個 label
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-html
  namespace: <your-name>
data:
  index.html: |
    <html><body><h1>Hello from <your-name></h1></body></html>
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  namespace: <your-name>
spec:
  replicas: 2
  selector:
    matchLabels: { app: web }
  template:
    metadata:
      labels: { app: web }
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpine
          ports: [{ containerPort: 80 }]
          volumeMounts:
            - { name: html, mountPath: /usr/share/nginx/html }
      volumes:
        - name: html
          configMap: { name: web-html }
---
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: <your-name>
spec:
  selector: { app: web }
  ports: [{ name: http, port: 80, targetPort: 80 }]
---
apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: web
  namespace: <your-name>
spec:
  hosts: ["<your-name>.dough-ops.com"]
  gateways: ["istio/k8s-gateway"]   # 整個叢集共用的 Gateway,跨 namespace 引用
  http:
    - route:
        - destination:
            host: web.<your-name>.svc.cluster.local
            port: { number: 80 }
部署
$ kubectl apply -f ~/my-app.yaml
$ kubectl -n <your-name> rollout status deployment/web --timeout=120s
# 成功之後開瀏覽器:https://<your-name>.dough-ops.com/

幾件會影響你的事,先知道比較不會卡關

🔑

網址自動被 Cloudflare Access 擋住

*.dough-ops.com 掛在同一個萬用字元 Access Application 下面——你的新 網址不需要額外設定就會自動套用同一個規則:只有登入 doughops GitHub org 的人看得到(showcase 頁面目前也是刻意維持這個預設,沒有另外 放行)。想開放給所有人看,需要另外在 Cloudflare 手動建一個 decision: bypass 的精確匹配規則,不是 ansible 管的範圍,見 Cloudflare 手動設定清單。

🌐

hostname 一定要在 *.dough-ops.com 底下

共用 Gateway(istio/k8s-gateway)只監聽這個萬用字元——用其他網域完全 連不進來,見 Role: istio。

📦

image pull 不用另外設定

節點走 mgmt-net 有 SNAT 出口,一般公開 image(Docker Hub、GHCR……) 直接拉得到。私有 registry 就照 Kubernetes 標準做法帶 imagePullSecrets,這個叢集沒有額外限制。

💾

需要持久化儲存就掛 PVC

兩個 StorageClass 可以直接用,都是 ReadWriteMany、同一個 NFS 後端: nfs-csi(PVC 刪掉資料跟著刪)跟 nfs-csi-retain (PVC 刪掉資料保留)。挑哪個看你要不要「誤刪 PVC 也不會真的丟資料」這層保險。

🔑

需要密鑰就用 Vault,不要寫死進 manifest

叢集裝了 vault-secrets-operator,任何 namespace 建一個 VaultStaticSecret(見下方範例),就會 自動同步出一個一般的 k8s Secret,跟平常 envFrom/volumeMounts 掛法完全一樣。不需要 額外指定 vaultConnectionRef/vaultAuthRef ——已經幫全部 namespace 接好共用的預設值。

先在 Vault 裡放一筆(從 bastion,或用 vault.dough-ops.com 的 UI)
$ vault kv put secret/<your-name>/db-password value=hunter2
在你的 namespace 裡建 VaultStaticSecret
apiVersion: secrets.hashicorp.com/v1beta1
kind: VaultStaticSecret
metadata:
  name: db-password
  namespace: <your-name>
spec:
  type: kv-v2
  mount: secret
  path: <your-name>/db-password
  destination:
    name: db-password-secret   # 同步出來的 k8s Secret 名稱
    create: true
  refreshAfter: 1h              # Vault 裡改了值,最晚等這麼久會自動重新同步

3. 目前有哪些服務可以用

全部走同一條路徑:*.dough-ops.com → Cloudflare Tunnel → Istio ingress gateway → 各自的 VirtualService。除了下表特別標「公開」的兩個,其餘全部只有 doughops GitHub org 成員登入後看得到——這是整個叢集的預設行為,不是每個服務各自 決定的。

HashiCorp Vaultvault.dough-ops.com秘密管理——網頁 UI/API,跑在 bastion 上,不是叢集內服務,見 Role: vaultCloudflare Access,登入後直接 OIDC 免密碼進 Vault(任何 doughops org 成員都是完整權限,見該頁說明)
ArgoCDargocd.dough-ops.comGitOps 持續部署,內建 in-cluster target,裝完就能管理這個叢集自己Cloudflare Access,登入頁有 OIDC 選項(免密碼、直接 admin)+ 備援用的 ArgoCD 自己 admin 帳密(見 內部工具怎麼查初始密碼)
